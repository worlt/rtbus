# 语音、震动与单车上下车提醒验收

适用：Android v16 本地优化候选包（实时公交.D）。2026-11-27 用户反馈真实乘车测试已经试过、可以使用；已接受该实际使用反馈，不要求重复相同乘车流程。下方保留逐项检查方法供后续按需定位，不代表所有锁屏 / 语音 / 自动结束组合已逐项确认。完整导航 / 性能证据见 [v15 记录](navigation-v15-device-validation.md)。

## 1. 安装哪个文件

- 多数安卓手机用 `build/rtbus-validation/RTBus-20261127-stable-v16-arm64.apk`；只有 32 位 ARM 旧机用同目录的 `RTBus-20261127-stable-v16-arm32.apk`。不要安装 release 目录的未签名文件。
- 把文件传到手机，用文件管理器点开安装。已有同签名「实时公交.D」时直接覆盖；若系统提示无法安装或签名不一致，记下原文，不要直接卸载或清除数据。
- 调试包标识 `com.github.u5151561.trackr.debug`，版本 0.1.14 / code 22。以 v16 文件名和[覆盖升级记录](stable-v16-upgrade-validation.md)中的哈希区分构建；该包继承 release 优化，但仍使用既有调试证书。

**当前进度：** 用户已确认实际乘车及日常功能可用；v16 已完成旧手机真实覆盖升级、数据逐文件保留和定向启动检查。卡顿排查继续暂停，不要求重复本清单。当前 code 22 不使用旧 code 21 包回退，也不通过卸载或清数据处理问题。

## 2. 先准备手机

1. 打开应用，允许通知；为后台追踪允许前台服务相关提示。
2. 可以保持手机平时使用的**静音模式**；首轮只关闭“勿扰”，确认系统没有禁用本应用通知渠道的震动。语音测试时另行调高媒体音量。普通静音与勿扰分开验收。
3. 在“我的”找到“语音播报提醒”“震动提醒”和“到站前提醒”。默认语音关闭、震动开启；到站前提醒先设 2 站。
4. 使用当前城市真实运营中的一条线路，核对方向、上车站和车辆车牌/自编号。全国城市支持范围未因此改变，不限指定城市。
5. 为锁屏一轮允许系统中的后台运行/电池不受限制；具体名称因手机而异。

## 3. 不坐车先测两个开关（约 5–10 分钟）

在线路详情里选择上车站，用铃铛/定时提醒入口设为几分钟后的一次性提醒。首轮关闭“到点自动开始追踪”，这样能单独检查定时通知。

| 语音播报提醒 | 震动提醒 | 预期 |
| --- | --- | --- |
| 关 | 开 | 发通知、震动，不朗读 |
| 开 | 关 | 发通知、朗读，不震动 |
| 开 | 开 | 发通知、朗读并震动 |
| 关 | 关 | 仍发通知，不朗读、不震动 |

每次切换后重新设下一次提醒；至少一轮退出应用再打开，确认开关被保存。“语音关闭”控制朗读，系统通知提示音由系统通知设置控制，不保证完全静音。

开启“到点自动开始追踪”且系统准许时，到点会开始追踪，临近/到站时再按开关反馈；系统拒绝自动启动时应降级为带“开始追踪”的通知，不能凭空显示正在追踪。

## 4. 追踪一辆还没到的车（约一班车）

1. 搜索线路并进入详情，先选你等待的上车站，核对行驶方向。
2. 点线路上的目标公交车或车辆列表中的某辆车，进入单车详情。
3. 点“追这辆车 · 到「某站」提醒上车”。目标车必须尚未开过上车站。
4. 观察车牌/自编号和目标站：一直追这一辆；其他车先到时不应冒充目标车提醒。
5. 临近（默认 2 站内）和到站分别提醒一次，文案应为“准备上车/请上车”，按两个开关决定是否朗读和震动。
6. 切后台、锁屏继续等一轮：通知进度持续更新，临近/到站仍按设置提醒。目标车临时没数据时应保留目标并提示信号问题，不能自动换车。
7. 已开过所选上车站的车不能开启该站候车追踪；结束这辆车的追踪不影响其他线路任务。

## 5. 我已上车 → 选下车站（一次真实乘车）

1. 进入线路详情，核对方向。**页面底部固定显示“我已上车 · 选择下车站”**，位于“追踪这班车”和换向、乘车码按钮的上方；无需先点公交图标或展开单车卡片。
2. 在站点总览点此按钮，会列出车牌/自编号和车辆所在站附近信息：按车牌选实际乘坐的车辆，再选下车站。如果已进入单车详情，则直接为当前车辆选站。没有候车追踪也能使用；无有效在途车或车辆已到终点时入口显示但不可用。
3. 只应列出前方尚未到达的站；过去站不可选。选站后必须再点“开启下车提醒”，取消不能启动。
4. 确认后保持同一车牌/自编号，目标变为所选下车站；原同车提醒被替换，不叠两个下车提醒。
5. 距目标阈值内、确认停靠时分别提醒“准备下车/请下车”，按语音和震动开关反馈。短 ETA 只是临近；确认目标车停靠目标站时，提醒后立即自动结束这份下车追踪，不必等车辆驶过站。“上车后自动结束追踪”不参与这份下车追踪的定位判定。
6. 修改下车目标后只保留新目标；其他车辆、其他线路的任务仍在。
7. 选站期间车辆前进到已选站，已到站的选择应失效，要求重选；车辆暂时离线时不能凭旧页面确认。
8. 锁屏完成其中一轮。公交数据可能延迟，实际乘车仍留意车内报站和路况。

### v5：不用等到站的详情复测

- 在任务进行时看单车卡：卡头显示「下车站：…」，行程中同一站标「我的下车站」。剩余站数和预计时间应指向下车站，不是线路终点；固定底栏只有一个「结束追踪」，另一个操作是「更改下车站」。
- 返回站点总览，可直接点「返回单车跟随」；留在总览刷新不应被拉回。再回首页点原追踪卡，应直接回同一辆车、同一个下车站，不用打开全线车辆列表。
- 试一次改站：取消保留旧站，确认后只标新站；车辆暂时没有实时位置时，不应换车或展示别的车的预计时间。手动结束后再进，不恢复旧任务。

### v6：区别短暂切出与行程过期

1. 建立一份测试用的下车提醒，看到所选车辆的预计剩余时间后回首页；短暂切出再返回，卡仍应打开原车和下车站。标准首页卡片右上角「结束」可直接取消这一趟，不必点进详情。
2. 用这份测试行程模拟丢信号：断开网络，记下最后看到的目标站 ETA。失联期间首页应提示「暂无车辆位置」，不显示旧 ETA。等原预计到站时刻过去至少 10 分钟后打开首页；如果一直没有 ETA，从最后见车（从没见车则从选站）起等 30 分钟。旧卡应已消失，不补发“请下车”。无需更改手机系统时间。
3. 再打开一次确认旧卡没有复活。测试后恢复网络；实际乘车有实时数据时，不应仅因原 ETA 已到就停掉提醒。

### v7：首页过期提示与收藏前三条

- 使用本页第 1 节的测试包。按上面的 v6 步骤让一份指定车下车提醒失联过期：在首页清理或重新打开时清理，都应看到「线路 · 下车站：未能确认到站，已清除过期的下车提醒。」看到后再返回首页，不重复提示；其他行程不受影响，手动结束或正常到站不显示这句。
- 首页当前筛选下有 3 条收藏时应全部可点，没有展开入口；添加第 4 条，重新打开应用，仍按原顺序显示前 3 条。点「收藏（4）」展开，再点收回；切换城市或分组后，以筛选结果为准。长辈版在「我常坐的车」上同样操作。

### v8：「我已上车」按到候车站的先后选车

1. 打开有多辆在途车的线路，选一个候车站，点「我已上车 · 选择下车站」。在「选择你乘坐的车辆」里核对候车站名，点排序菜单切到「先到的在前」。
2. 核对车辆：在本站停靠的优先；有本站预测时看预计到站时间，没有则看剩余站数；仍有前方下车站的已过站车辆在后面，也能选。切回「默认顺序」应恢复数据源顺序，切换本身不选车、不创建提醒。
3. 点实际车牌，再选前方下车站，核对单车跟随的车牌和下车站。重新打开选车弹窗，应沿用上次的排序偏好。

### v9：不用出门，检查断网和两车同站

1. **断网时不误开。** 在家打开一条有实时车的线路，选车并点选前方下车站，先不要确认。暂时断开 Wi-Fi 和移动数据；等刷新失败后，确认按钮应不能点。恢复网络，等同一辆车的新位置回来；只有仍在前方的站能确认。仅打开弹窗不创建提醒，若只是试用可点取消。
2. **不同车互不覆盖。** 在线路仍有两辆可选车、两车均未到同一目的站时，给 A 车建下车提醒；回总览，显式选 B 车并选同一站。回首页应有两份提醒。打开其中一张卡核对车牌，再结束这份，另一份应仍在。测试完成只清理这次建立的任务。

### v10：首页看指定车辆在哪一站

1. 给一辆在途车设置下车提醒，返回首页。确认预计下车时间仍在；行驶中应显示「下一站：…」，停靠时应显示「停靠：…」。点卡片核对同一辆车，别把位置站名当成下车目标。
2. 两辆车都在追踪时，核对每张卡跟的是自己的车。切长辈版再核对一次。重连时如果详情已恢复、首页仍显示「暂无车辆位置」，记录显示差异持续多久；断网期间不应把旧站名显示成当前位置。

### v12：首页车牌、重连与下拉更新

1. 标准版和长辈版：首页两张卡分别显示所选车的「车牌/车号」，可与详情核对；位置暂不可用时，保留有效车号，不显示内部 ID 或旧站名。
2. 不实乘也能测。用在途车、靠后的下车站开测试提醒。断开 Wi-Fi 和移动数据到首页提示「暂无车辆位置」，再联网，留在首页，不用先开详情或下拉。网络确认可用后应尝试提前补查；是否有位置取决于接口响应及是否包含该车，不以 1 秒作为通过线。两张卡可在不同时间恢复。
3. 联网时在标准版首页下拉，应请求更新正在等待下一轮的已上车追踪，不需等原有轮询；刚查过的短时间内会合并刷新，正在查的不会另发并行请求。长辈版保留自动恢复，不新增下拉手势。
4. 用完结束测试提醒。不要用真实乘车那条提醒做断网模拟；真实乘车独立验证锁屏、通知/震动、实际到站及自动结束。

## 6. v13 无人工测试入口

不再通过「测试震动」或「测试到站提醒」验收；这两个入口已注释，真实通知和震动未关闭。不坐车时可用第 3 节的定时提醒检查设置。实际乘车走下节。

## 7. v4 真实到站与自动结束专项

1. **候车**：按第 4 节追一辆尚未到站的目标车。先收到临近提醒；ETA 30 秒等短预测不得用掉已到站标记，单线路追踪卡/常驻通知也不提前写“到站了”。确认该车停靠或轮询跳过停靠后，须再发“请上车”及一组震动。仍是候车时，不因目标车刚停下就把它当成已下车结束；指定车过站后按原行为结束，普通不指定车候车仍可等下一班。
2. **下车**：按第 5 节点“我已上车”，选实际车辆和前方目标站，锁屏实乘。确认停靠目标站时须发“请下车”和到站震动，并自动结束这份追踪；不等待离站数据。如果两次轮询直接越过目标站，应补发到站提醒并结束。
3. 自动结束后，常驻进度和“追踪中”消失；刚发的最终到站通知保留，点击可消除，未操作约五分钟过期。其他同时追踪的任务不受影响。
4. 关闭应用震动再测：仍有到站通知，已上车任务仍正常结束，但不震动。手动“结束”仍清理该任务旧临近/到站通知。语音开关单独按第 3 节组合验收。
5. 若仍“临近震、到站不震”，记下发生时间、候车/下车、是否有到站通知、追踪是否自动结束及当时是否锁屏。无须寻找诊断按钮。
6. 若没有新的真实 ARRIVED 记录，先检查剩余站数/ETA/已停靠及数据更新时间，不能把“服务未产生到站事件”误判为马达故障；有 ARRIVED 且 REQUESTED 仍无马达反馈时，再检查设备实际策略。连接 adb 可补采 `ArrivalAlertManager` / `ReminderVibration` 日志。

## 8. 遇到没震动、没语音或追踪异常

- 没震动：普通静音可以保留。确认安装的是本轮新 APK，并检查应用“震动提醒”开启、通知权限开启、系统相应提醒渠道允许震动、勿扰关闭；系统全局禁震/震动强度也会影响实际马达。应用不会覆盖系统手动禁用的渠道震动。若仍不震动，可保存当时通知和系统渠道设置截图，再按下方格式反馈。
- 没语音：确认应用“语音播报提醒”开启、媒体音量合适，系统文字转语音引擎可用且装有中文语音；播放音乐、蓝牙耳机等音频路由也会影响听感。
- 定时晚响或锁屏不更新：记录系统电池限制、精确闹钟权限与通知状态，先用应用前台对照测试。
- 实时没数据：记录页面时间和联网状态；不能把公交服务接口缺失的数据认定为已到站。

反馈格式：手机型号 / Android 与系统版本；城市、线路、方向、车辆编号；上车站和下车站；语音/震动开关状态；发生时间；前台/后台/锁屏；预期与实际；截图或录屏。无需提供家庭住址或完整出行记录。

## 9. 顶部留白与间距（本轮保持不变）

1. 冷启动到公交首页：保留原版展开大标题，去掉大标题上方空导航行的多余空间；目测标题上方与到搜索框之间的留白接近。普通字体下可见展开区约 80dp、收起区 64dp，均另加状态栏安全区；搜索与标题栏保持 12dp 留距。特别大字体会自适应放宽，不能为压间距裁字。
2. 连续上滑列表、滑回顶部，再在顶部继续滑动 2–3 次：大标题仍按原版过渡收起/展开，展开高度不能累积增加；下拉刷新可使用。收起后搜索框与顶栏不挤在一起。
3. 切“我的”重复上述滚动：同样保留原版大标题过渡，列表首组在顶栏下至少留 16dp 空间；列表不会贴住或覆盖标题。
4. 浅色/深色切换、小屏和系统较大字体各检查一轮：标题和入口可读可点；城市切换、搜索、乘车码和底部页签仍可使用。

## 10. 本轮验收边界

主机回归、Robolectric 和 APK 静态检查可验证代码路径、UI 操作、开关组合、任务隔离及签名/对齐，不能证明手机马达、扬声器、厂商后台策略或真实公交到站已验收。v9 的同站双车及断网防误开已按用户反馈在真机通过。v10 首页位置与详情已完成用户首轮核对；用户反馈 v12 本轮非实乘复测通过，包括首页重连、下拉刷新和车牌核对；2026-11-27 用户进一步反馈真实乘车已经测试、可以使用；没有另列具体锁屏 / 开关 / 自动结束组合，不将概括反馈扩成逐项全部通过。iOS 未做实际构建和设备验收。
