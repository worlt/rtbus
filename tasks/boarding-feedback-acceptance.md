# 语音、震动与单车上下车提醒验收

适用：2026-11-26 Android 到站反馈修复 v3 debug 包（代码 `50d4f7b`，实时公交.D；保留普通静音兼容 v2、原版标题过渡及常驻上车入口）。用户已确认 v2 即时测试能震动、临近/追踪操作有震动，但实际到站未震；本清单用于 v3 到站专项复测，不代表此轮真实到站已验收。路线规划已移除，普通公交线路、线路定时提醒、候车追踪和下车提醒保留。

## 1. 安装哪个文件

- 多数近年的安卓手机：`androidApp/build/outputs/apk/debug/androidApp-arm64-v8a-debug.apk`。
- 只支持 32 位 ARM 的旧设备：同目录的 `androidApp-armeabi-v7a-debug.apk`。
- 为避免与旧构建混淆，本轮另存同内容副本 `build/rtbus-validation/RTBus-20261126-arrival-v3-arm64-debug.apk` 和 `RTBus-20261126-arrival-v3-arm32-debug.apk`；签名和原产物一致。
- 上述 debug 包使用本机既有 debug 签名，可直接安装；不要安装 release 目录里的 `*-unsigned.apk`。本轮未更新 release 包。
- 把 APK 传到手机后，用文件管理器打开，按系统提示允许本次安装。已装同签名实时公交.D 时尝试覆盖安装。若提示签名不一致，先记录原包来源并备份，不要直接卸载清数据。
- 调试包标识 `com.github.u5151561.trackr.debug`，版本 0.1.13 / code 21。相同版本号不能用于证明安装了新构建；以本轮交接记录的 SHA-256 为准。

## 2. 先准备手机

1. 打开应用，允许通知；为后台追踪允许前台服务相关提示。
2. 可以保持手机平时使用的**静音模式**；首轮只关闭“勿扰”，确认系统没有禁用本应用通知渠道的震动。语音测试时另行调高媒体音量。普通静音与勿扰分开验收。
3. 在“我的”找到“语音播报提醒”“震动提醒”和“到站前提醒”。默认语音关闭、震动开启；到站前提醒先设 2 站。
4. 使用当前城市真实运营中的一条线路，核对方向、上车站和车辆车牌/自编号。全国城市支持范围未因此改变，不限指定城市。
5. 为锁屏一轮允许系统中的后台运行/电池不受限制；具体名称因手机而异。

## 3. 不坐车先测两个开关（约 5–10 分钟）

在线路详情里选择上车站，用铃铛/定时提醒入口设为几分钟后的一次性提醒。首轮关闭“到点自动开始追踪”，这样能单独检查定时通知。

| 语音播报提醒 | 震动提醒 | 预期 |
| --- | --- | --- |
| 关 | 开 | 发通知、震动，不朗读 |
| 开 | 关 | 发通知、朗读，不震动 |
| 开 | 开 | 发通知、朗读并震动 |
| 关 | 关 | 仍发通知，不朗读、不震动 |

每次切换后重新设下一次提醒；至少一轮退出应用再打开，确认开关被保存。“语音关闭”控制朗读，系统通知提示音由系统通知设置控制，不保证完全静音。

开启“到点自动开始追踪”且系统准许时，到点会开始追踪，临近/到站时再按开关反馈；系统拒绝自动启动时应降级为带“开始追踪”的通知，不能凭空显示正在追踪。

## 4. 追踪一辆还没到的车（约一班车）

1. 搜索线路并进入详情，先选你等待的上车站，核对行驶方向。
2. 点线路上的目标公交车或车辆列表中的某辆车，进入单车详情。
3. 点“追这辆车 · 到「某站」提醒上车”。目标车必须尚未开过上车站。
4. 观察车牌/自编号和目标站：一直追这一辆；其他车先到时不应冒充目标车提醒。
5. 临近（默认 2 站内）和到站分别提醒一次，文案应为“准备上车/请上车”，按两个开关决定是否朗读和震动。
6. 切后台、锁屏继续等一轮：通知进度持续更新，临近/到站仍按设置提醒。目标车临时没数据时应保留目标并提示信号问题，不能自动换车。
7. 已开过所选上车站的车不能开启该站候车追踪；结束这辆车的追踪不影响其他线路任务。

## 5. 我已上车 → 选下车站（一次真实乘车）

1. 进入线路详情，核对方向。**页面底部固定显示“我已上车 · 选择下车站”**，位于“追踪这班车”和换向、乘车码按钮的上方；无需先点公交图标或展开单车卡片。
2. 在站点总览点此按钮，会列出车牌/自编号和车辆所在站附近信息：按车牌选实际乘坐的车辆，再选下车站。如果已进入单车详情，则直接为当前车辆选站。没有候车追踪也能使用；无有效在途车或车辆已到终点时入口显示但不可用。
3. 只应列出前方尚未到达的站；过去站不可选。选站后必须再点“开启下车提醒”，取消不能启动。
4. 确认后保持同一车牌/自编号，目标变为所选下车站；原同车提醒被替换，不叠两个下车提醒。
5. 距目标阈值内、进站时应分别提醒“准备下车/请下车”，按语音和震动开关反馈；“上车后自动结束追踪”不能把这份下车提醒误关掉。
6. 修改下车目标后只保留新目标；其他车辆、其他线路的任务仍在。
7. 选站期间车辆前进到已选站，已到站的选择应失效，要求重选；车辆暂时离线时不能凭旧页面确认。
8. 锁屏完成其中一轮。公交数据可能延迟，实际乘车仍留意车内报站和路况。

## 6. 静音震动专项（先立即测试，再验证锁屏提醒）

最新用户实测：普通静音下“测试震动”已成功，临近/追踪操作也有震动，实际到站仍无震动。v3 统一到站为同一有限分段效果，并修复自然完成当轮立即撤销最终到站通知的问题；这两项代码与主机验证不能代替手机上的到站复测。

1. 手机保持平时的普通静音，先关闭“勿扰”；应用“语音播报提醒”关、“震动提醒”开。
2. 打开“我的 → 测试震动”（震动开关下方），无需设线路或等待公交。确认报告新增“到站反馈：分段提醒修复 v3”（同时保留 v2 底层兼容标记），并观察是否实际连续震动。此按钮只请求震动，不播放语音或铃声。
3. `REQUESTED` 表示已调用系统接口，不是马达成功回执。若仍没震，截图整个结果弹窗；报告含机型、系统、铃声模式/音量、勿扰、通知权限和渠道震动。文字可长按选择复制；可点“系统提醒设置”，按报告检查后关闭弹窗重测。若没有“分段提醒修复 v3”标记，先确认安装的是本轮包。
4. 若结果为 `SWITCH_OFF`、`NOTIFICATIONS_OFF`、`CHANNEL_OFF`、`CHANNEL_VIBRATION_OFF` 或 `DND`，按中文原因检查相应开关；应用不会强行更改这些设置。
5. 关闭应用“震动提醒”再点测试：应不震动并明确提示开关已关。重新打开后再测。开启勿扰做一轮对照，应用不额外请求跨越勿扰的震动。
6. 即时测试有效后，在线路详情设一条 1–2 分钟后的定时提醒，关闭“到点自动开始追踪”；前台和锁屏各一轮，预期有通知及震动、不朗读。即时按钮不能代替锁屏/后台验收。
7. 在系统通知设置手动关闭提醒渠道的震动，测试不应被应用强行恢复；重新允许后再测试。普通响铃与振动模式各测一轮，单条到站/定时通知不应触发两次独立震动。

## 7. v3 到站专项（本轮重点）

1. 保持普通静音、勿扰关闭，应用震动开、语音关；按第 4 节追一辆尚未到的车。确认同一车牌先出现临近提醒并震动，随后“车辆已到站 / 请上车”时再有一组分段震动。
2. 按第 5 节选择实际乘坐车辆及前方下车站，锁屏实乘；留意“请下车”及到站分段震动。若两轮数据之间车辆已过站，补发的最终到站提醒也应正常反馈。
3. 行程自然完成时，常驻进度通知与“追踪中”应结束；本轮刚发出的最终到站提醒仍可看到，点击可消除，未操作约五分钟自动过期，不能与常驻进度同一瞬间被清掉。
4. 关闭应用震动再测一轮到站：仍有到站通知，但不震动。用户主动点“结束”时，旧临近/到站提醒仍应清除；其他追踪任务不受影响。
5. 如果临近震、已到站不震，请分别记录到站通知是否出现、是候车还是下车、追踪是否同时自动结束、屏幕是否锁定，并截取测试诊断。连接 adb 时可采集 `ArrivalAlertManager` 和 `ReminderVibration` 日志；前者新增 APPROACHING / ARRIVED 等事件及请求结果，不含线路或车牌。

## 8. 遇到没震动、没语音或追踪异常

- 没震动：普通静音可以保留。确认安装的是本轮新 APK，并检查应用“震动提醒”开启、通知权限开启、系统相应提醒渠道允许震动、勿扰关闭；系统全局禁震/震动强度也会影响实际马达。应用不会覆盖系统手动禁用的渠道震动。若仍不震动，先截图“测试震动”的完整结果，再按下方格式反馈；不必为获取首轮诊断再等一次公交。
- 没语音：确认应用“语音播报提醒”开启、媒体音量合适，系统文字转语音引擎可用且装有中文语音；播放音乐、蓝牙耳机等音频路由也会影响听感。
- 定时晚响或锁屏不更新：记录系统电池限制、精确闹钟权限与通知状态，先用应用前台对照测试。
- 实时没数据：记录页面时间和联网状态；不能把公交服务接口缺失的数据认定为已到站。

反馈格式：手机型号 / Android 与系统版本；城市、线路、方向、车辆编号；上车站和下车站；语音/震动开关状态；发生时间；前台/后台/锁屏；预期与实际；截图或录屏。无需提供家庭住址或完整出行记录。

## 8. 顶部留白与间距

1. 冷启动到公交首页：保留原版展开大标题，去掉大标题上方空导航行的多余空间；目测标题上方与到搜索框之间的留白接近。普通字体下可见展开区约 80dp、收起区 64dp，均另加状态栏安全区；搜索与标题栏保持 12dp 留距。特别大字体会自适应放宽，不能为压间距裁字。
2. 连续上滑列表、滑回顶部，再在顶部继续滑动 2–3 次：大标题仍按原版过渡收起/展开，展开高度不能累积增加；下拉刷新可使用。收起后搜索框与顶栏不挤在一起。
3. 切“我的”重复上述滚动：同样保留原版大标题过渡，列表首组在顶栏下至少留 16dp 空间；列表不会贴住或覆盖标题。
4. 浅色/深色切换、小屏和系统较大字体各检查一轮：标题和入口可读可点；城市切换、搜索、乘车码和底部页签仍可使用。
